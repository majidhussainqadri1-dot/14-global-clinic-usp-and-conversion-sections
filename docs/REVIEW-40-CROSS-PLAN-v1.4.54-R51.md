## Two newly confirmed source defects (before any R51 code edits)

**R51-D01 — FUT22 Public Policy Change Log completeness.** `GCU_Future_Intelligence::public_change_log()` scans only at most 1,000 active public-history candidates (ten pages ×100). It returns `$out` as if this were the verified whole requested history even if the tenth page had 100 invalid legacy entries and fewer than `$limit` approved entries were accumulated. Older approved entries may exist after the bounded window. It is correctly resource-bounded, but an *unverified tail* is silently treated like the genuine end of all results. Correction must **retain bounded paging** yet return an explicit `WP_Error` with 503 and a privacy-safe static operational signal if the maximum examined page is full, output is still short of requested count, and no known end-of-data was seen. A genuine DB-empty or short terminal page must continue to return valid `[]`. `rest_change_log()` and `render_change_log()` already have error propagation/generic unavailable messaging and should remain consistent. The maximal cap is a known evidence limitation, NOT a claim actual live policy history is wrong.

**R51-D02 — FUT06 Jurisdiction Disclosure read evidence.** `GCU_Future_Intelligence::jurisdiction_disclosure()` currently executes the approved regional/general SQL query, but loops over `is_array($rows)?$rows:[]`; WPDB `get_results=false/null` silently becomes identical to proven *no approved regional or generic notice*. The public Future UI omits a disclosure with no failure explanation or operator-visible error. Source correction must fail closed, **never invent regional legal information**, distinguish unverifiable SQL from verified empty/non-approved data, log only static code, and render a neutral public temporarily-unavailable message when the read is unverified. Approved PK-specific→ZZ general fallback and valid-policy checks must remain; invalid country input must not escalate to special region. No data/private personal content in errors.
